# openbyok — VS Code Extension (BYOK)

Super-lightweight extension that registers OpenCode Console models as VS Code
BYOK (Bring Your Own Key). **No local OpenCode CLI or database required.**

Pure CommonJS, **zero npm dependencies**, no build step. Modular layout:
`src/extension.js` is wiring only; logic lives in `src/core/` (services, providers)
and `src/features/` (byok, benchmark, opengit).

## Features
- Register an OpenCode Console token (`st_…`) via device flow (browser or manual URL), or auto-retrieve from the OpenCode CLI when it is detected on the machine
- Two-step model picker: choose a **provider**, then its models (statused OK / SLOW / TIMEOUT / ERROR / NO_TOKENS / UNKNOWN from the benchmark cache)
- **Consolidated metadata**: context window, output limits, vision, tool calling, reasoning effort — merged from the Console API and the static catalogue
- Auto-generates `chatLanguageModels.json` groups named `OpenBYOK <provider>` (vendor `customendpoint`, apiType `chat-completions`)
- Console token stored in VS Code SecretStorage (encrypted, OS-level) with automatic refresh + retry-on-401 network wrapper (`authFetch`)
- Background benchmark cache (`~/.openbyok-benchmark-cache.json`, TTL 2 h) refreshed only when expired, plus a cancellable progress command
- `OpenGIT`: generates a conventional commit message from the git diff and prefills the Source Control input box (never commits directly)

## Installation (from source — no compilation needed)

This extension is **pure JavaScript** (CommonJS). There is **no build step, no TypeScript, no compilation**.
You can install it directly from the source folder and modify the code on the fly.

### Option A — Install as unpacked extension (recommended for dev)

1. Open VS Code
2. `Ctrl+Shift+P` → "Developer: Install Extension from Location..."
3. Select the `vscode/` folder
4. The extension is now active — edit any file under `src/` and reload the window (`Ctrl+Shift+P` → "Developer: Reload Window") to apply changes

### Option B — Symlink into extensions folder

```bash
# Windows (PowerShell, run as admin or enable developer mode)
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\.vscode\extensions\openbyok" -Target "REDACTED_LOCAL_PATH"
```

Then reload VS Code. Any edit to `src/extension.js` takes effect after a window reload.

### Option C — Package as .vsix (no compile)

```bash
npm install -g @vscode/vsce
cd vscode/
vsce package --no-dependencies
# produces openbyok-0.1.0.vsix
code --install-extension openbyok-0.1.0.vsix
```

### Hot-reload workflow

1. Edit the relevant module under `src/`
2. `Ctrl+Shift+P` → "Developer: Reload Window"
3. No recompilation needed — VS Code re-reads the source on every load

## Usage
1. `Ctrl+Shift+P` → "OpenBYOK: Register API Token (st_…)" (device flow, browser or manual URL)
2. `Ctrl+Shift+P` → "OpenBYOK: Select Models for BYOK" → pick a provider, then its models
3. On first use (no fresh cache) you are offered "Run Benchmark" (progress bar, cancellable) or "Skip (show all)"
4. `Ctrl+Shift+P` → "OpenBYOK: Configure Group API Key (native)", or open **Manage Language Models**, click the gear on the `OpenBYOK …` group → **Update API Key** and paste your OpenCode key
5. `Ctrl+Shift+P` → "Developer: Reload Window" so the models appear in the model picker

### Other commands
| Command | Effect |
|---------|--------|
| `OpenBYOK: Refresh Token` | force a `refresh_token` round-trip |
| `OpenBYOK: Logout` | delete the 4 SecretStorage keys |
| `OpenBYOK: Run Benchmark (with progress)` | live benchmark, writes the cache |
| `OpenBYOK: Clear Benchmark Cache` | wipe memory cache + JSON file |
| `OpenGIT: Générer un message de commit` | SCM title-bar button, prefills the commit box |

## Credentials model (important)
Two different secrets are involved and must not be mixed up:
- the **Console token** `st_…` used by this extension to call the Console API → VS Code SecretStorage (`openbyok.opencode.token` + `.refresh` / `.server` / `.expires`);
- the **BYOK key** used by Copilot Chat to call the models → a native VS Code secret referenced as `${input:chat.lm.secret.X}`.

This extension never invents a `chat.lm.secret.X` id: those ids are generated by VS Code itself when the user sets the key through *Manage Language Models → Update API Key*. A brand-new group is written with an empty `apiKey: ""` placeholder so the group shows up in the panel; re-selecting an existing group keeps its current reference. Groups always use the core-known vendor `customendpoint`.

The `OpenCode Go` group (vendor `opencodego`, provided by another extension) is never touched.

## Independence
This extension talks directly to:
- `https://opencode.ai/console/api/v2/config` (Console API)
- `https://models.opencode.ai/experimental/v2.0/api.json` (static catalogue)

It does NOT read `~/.local/share/opencode/opencode.db` and does NOT depend on
`@opencode/cli`. The optional CLI helper (`opencode auth export opencode`, or
`OPENCODE_CLI_PATH`) is only offered when the binary is actually detected, and
the legacy `~/.openbyok-console.json` token file has been removed — SecretStorage
is the single source of truth.

## Consolidation
Models are consolidated by merging:
1. Console OpenCode config → providers, baseURL, active models
2. Static catalogue → context/output limits, modalities, capabilities, costs

The NVIDIA provider entry is preferred when multiple catalogue entries exist for
the same model ID (matching the console OpenCode display values).

## Benchmark tuning
Defaults in `src/core/constants.js`: per-model timeout 15 s, concurrency 8,
cache TTL 2 h, SLOW thresholds TTFT > 5 s or < 5 tokens/s.

See `AGENTS.md` for the maintainer-oriented reference (architecture rules,
